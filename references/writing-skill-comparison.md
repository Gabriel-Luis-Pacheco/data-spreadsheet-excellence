# Comparative research: 5 humanization skills + 5 anti-slop writing skills

Reviewed for the **writing surfaces of Data & Spreadsheet Excellence** on 2026-10-22. This is a task-fit selection of ten relevant public skill projects, not a verified global ranking or an endorsement of every claim they make. The adaptation is original guidance, **not copied source text or vendored skills**. If updating this comparison, inspect the linked upstream SKILL.md, references, license and recent changes.

## Cross-skill conclusions (the reason these changes improve this *spreadsheet* skill)

**Common useful core, now explicit in references/human-writing-editorial.md:**
1. Existing author/workplace samples and task purpose determine voice; no default “humanized” persona.
2. Source data and exact workbook field semantics are stronger constraints than elegant prose.
3. Facts and unknowns come before writing style; editing may cut filler but not business evidence.
4. The final output must suit its medium: plain labels in Excel; no Markdown, chat scaffolding, invented section headings or execution logs in cells.
5. Use structure only for actual navigation/decisions; a simple operational ledger may need no narrative at all.
6. One targeted editing pass and an independent fact/meaning check are more useful than repeated generic rewrite loops.
7. Check naturally repeated clichés, transitions, rhetorical patterns and sentence rhythm **in context**, not as deterministic authorship signals.
8. Preserve mandated uncertainty, regulatory wording, technical labels, legally required disclosures and exact data values.
9. For explicit critique, identify literal phrases and the concrete edit. Never call something AI-authored from style alone.
10. Check the real delivered artifact, including row labels, table headers, chart captions and any user-facing summary.

**Not imported:** repository source code or copyrighted prose, bundled licenses, unrelated UI systems, detector evasion claims, hidden-Unicode manipulation, forced typos, artificial personalities, score-chasing, universal banword policies, mandatory “zero em dash”, automatic rewriting of imported datasets, and processes that require multiple reviewers for trivial text.

## Evaluation protocol

The comparison itself is not evidence that outputs from a model are better. For each evaluation, supply the same business facts and author sample to a model with old vs new skill under matched settings. Compare the **actual** report/workbook text blind on: fact retention (hard gate), source contract, specificity, task usefulness, concision, natural register, unnecessary sections/cells, required caveats and readability. Include negative tests where original formal language or a supplied blue-styled workbook must remain intact. Static repository tests validate packaging only; they do not prove future writing behavior.
